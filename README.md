# AnimeLib TV

Неофициальный клиент AnimeLib для Android TV и Google TV. Приложение открывает
`https://v5.animelib.org`, добавляет навигацию с пульта, полноэкранное видео и
локальную блокировку рекламы.

Проект не связан с владельцами AnimeLib. Товарные знаки и содержимое сайта
принадлежат их правообладателям.

## Возможности

- Android 11 и новее (`minSdk 30`)
- навигация по сайту крестовиной пульта и заметная подсветка фокуса
- сохранение cookies и авторизации между запусками
- полноэкранное видео через стандартный API WebView
- управление встроенным AnimeLib-плеером и плеерами внутри iframe: запуск,
  пауза, перемотка на 10 секунд и выбор качества
- выбор серий, озвучек и периодов в разделе «Сейчас смотрят»
- плавная прокрутка страницы и горизонтальных списков с удержанием кнопки пульта
- управление формами входа AnimeLib, VK и Google с вызовом TV-клавиатуры
- осторожная блокировка рекламы по умолчанию
- усиленный режим и полное отключение блокировки
- проверка обновлений через GitHub Releases и установка скачанного APK

Настройки блокировки открываются кнопкой `⚙` в правом нижнем углу сайта или
клавишей Menu/Settings на пульте. При выборе видео AnimeLib первое нажатие OK
сразу запускает его и передаёт управление плееру. При выборе iframe Kodik первое
нажатие OK передаёт управление внутрь плеера. Стрелка вниз открывает панель, крестовина выбирает качество и
другие элементы, а OK активирует выбранный пункт. Без выбранного элемента
стрелки влево и вправо перематывают видео на 10 секунд. Кнопка «Назад» сначала
возвращает управление странице, затем открывает предыдущую страницу сайта.
Кнопки Channel/Page Up и Down плавно прокручивают страницу.
Во внешнем окне авторизации первое нажатие OK передаёт фокус окну, стрелки
переключают его поля, а повторное OK активирует выбранный элемент. Для полей
ввода автоматически открывается экранная клавиатура.

## Сборка

Требуются Android Studio с Android SDK Platform 36, JDK 17 и Android SDK Build
Tools 36.0.0. Откройте корень проекта в Android Studio, дождитесь синхронизации
Gradle и соберите `debug`-вариант.

После добавления Gradle Wrapper сборка из терминала выполняется командой:

```powershell
.\gradlew.bat assembleDebug
```

APK появится в `app/build/outputs/apk/debug/`.

На GitHub сборка запускается автоматически для ветки `main`. Готовый APK можно
скачать из раздела **Actions → Build APK → Artifacts**. Debug APK подходит для
тестирования; постоянные публичные релизы позже следует подписать отдельным
ключом, хранящимся в GitHub Secrets.

## Проверка на телевизоре

В Android Studio Device Manager создайте устройство категории TV с образом
Google TV или Android TV API 35–37 и разрешением 4K. Для проверки реального
пульта полезно дополнительно установить APK на физический телевизор через ADB.

Основные сценарии проверки:

1. Навигация по главной, каталогу, поиску и форме входа.
2. Сохранение входа после перезапуска приложения.
3. Запуск Kodik и альтернативного AnimeLib-плеера, вход и выход из fullscreen.
4. Переключение трёх режимов блокировки и запуск видео в каждом режиме.
5. Поведение кнопки «Назад» внутри плеера, истории сайта и на главной странице.

## Ограничения

AnimeLib может менять разметку и адреса рекламных сервисов без обновления
приложения. Правила блокировки намеренно консервативны, чтобы не ломать видео.
Разметка элементов управления внешних плееров может меняться, поэтому их
поведение нужно проверять на актуальной версии Android System WebView.

## Обновления

Репозиторий обновлений задан в
`app/src/main/java/org/animelibtv/app/UpdateConfig.kt`. Приложение проверяет
последний GitHub Release при запуске не чаще одного раза в 12 часов. Ручная
проверка доступна в меню настроек.

Добавляйте к релизу подписанный APK с именем `AnimeLibTV.apk`. Если файла с таким
именем нет, приложение выберет первый APK в релизе. Перед установкой проверяются
имя пакета и сертификат подписи. Android показывает системное подтверждение
установки, а при первом обновлении также попросит разрешить установку из этого
источника. Все публичные версии должны быть подписаны одним постоянным ключом.

Workflow `Publish release APK` создаёт GitHub Release при отправке тега `v*`.
Для него нужно добавить в GitHub Actions Secrets:

- `ANDROID_SIGNING_KEYSTORE_BASE64` — keystore в Base64;
- `ANDROID_SIGNING_STORE_PASSWORD`;
- `ANDROID_SIGNING_KEY_ALIAS`;
- `ANDROID_SIGNING_KEY_PASSWORD`.

Перед каждым релизом увеличьте `versionCode` и `versionName` в
`app/build.gradle.kts`, затем создайте соответствующий тег, например `v0.2.0`.
